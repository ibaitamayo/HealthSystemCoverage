# Privacy and security

Never post credentials, cohort membership, patient event logs, clinical notes,
real diagnostic reports or identifying screenshots in a public issue.

Use database roles with SELECT-only access. The package constructs analytical
SELECT queries; a read-only session is not a substitute for server permissions.
Keep local membership/event objects on approved infrastructure and exclude them
from version control and synchronization.

Native process-map frequencies are not small-cell suppressed. Reports are not
automatically anonymized or approved for external distribution. Review rare
combinations, counts and overlapping outputs before sharing.

Report vulnerabilities privately to the verified maintainer listed in
DESCRIPTION, without sending patient data or secrets. If that contact is still
a placeholder, obtain a verified contact first; do not post sensitive output.
